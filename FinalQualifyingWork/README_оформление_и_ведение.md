# Требования к оформлению и ведению ВКР

Документ фиксирует принятые решения по оформлению и дальнейшему обновлению ВКР
`БояриновИР_ВКР_черновик.docx`.

## 1. Назначение

Работа: **"Разработка системы отслеживания БВС с использованием данных с
рычагов управления и видеопотока с курсовой камеры"**.

Файл является рабочим черновиком. Титульный лист пока заменяется заглушкой:

> ТИТУЛЬНЫЙ ЛИСТ БУДЕТ ДОБАВЛЕН ОТДЕЛЬНО

## 2. Базовый стиль оформления

Ориентир по стилю - предыдущая работа автора:
`БояриновИР_Дипломная работа печать.pdf`.

Использовать:

- порядок разделов: титульный лист, реферат, содержание, перечень сокращений,
  введение, главы, заключение, список источников, приложения;
- сквозную нумерацию страниц;
- нумерацию глав арабскими цифрами;
- нумерацию подразделов вида `1.1`, `1.2`, `2.1`;
- подписи рисунков вида `Рисунок 1.1 - ...`;
- подписи таблиц вида `Таблица 1.1 - ...`;
- приложения с буквенными обозначениями: `ПРИЛОЖЕНИЕ А`, `ПРИЛОЖЕНИЕ Б`.

## 3. Согласованная структура

Основных глав - 4:

1. Анализ предметной области и требований к системе отслеживания БВС.
2. Разработка архитектуры программно-аппаратного комплекса отслеживания БВС.
3. Разработка и исследование алгоритмов отслеживания БВС по RC-каналам и
   видеопотоку.
4. Интеграция комплекса с внешней системой мониторинга БВС.

Глава 3 содержит алгоритмы и все экспериментальные результаты. Глава 4
начинается только после того, как система уже готова и требуется интеграция с
NebosvodConnect/"Небосвод".

## 4. Терминология

- В формальных разделах использовать термин **БВС**.
- В технических разделах после первого упоминания допустимо использовать
  **FPV-дрон исследуемого класса**.
- После первого упоминания "рычагов управления" использовать более точный
  термин **RC-каналы**.
- Основной рабочий алгоритм локализации - **Particle Filter**. Фильтр Калмана не
  описывать как основной метод.
- Камерные наблюдения формулировать как "формирование камерных наблюдений по
  видеопотоку"; при техническом описании указывать, что на текущем этапе
  генерация выполнялась offline из-за ограничений вычислительных ресурсов.

## 5. Принятые содержательные решения

- Объект исследования: процесс отслеживания местоположения БВС в условиях
  отсутствия бортовых навигационных систем.
- Предмет исследования: разработка системы отслеживания БВС с использованием
  данных с рычагов управления и видеопотока с курсовой камеры.
- Научная новизна: вычисление координат выполняется на наземной станции на
  основе RC-каналов и видеопотока без установки навигационного оборудования на
  БВС.
- Практическая значимость: прототип для FPV-дронов без GPS/ГЛОНАСС, пригодный
  для испытаний и передачи данных во внешнюю систему мониторинга.
- Конечный пользователь: эксплуатанты малоразмерных БВС, которым требуется
  мониторинг без установки бортовой навигационной аппаратуры.

## 6. Метрики

- В главе 3 основная исследовательская метрика - `p90_err_m`.
- Внутренний исследовательский критерий - `p90 < 15 м`.
- Для формального сопоставления с категориями HEPU/"Небосвод" требуется `p95`.
- Без камеры целевой уровень - HEPU 9.
- С камерой перспективно обсуждаются HEPU 10/11.

## 7. Аппаратная архитектура

Основные цепочки:

```text
EdgeTX/ELRS аппаратура -> ELRS-приёмник -> ESP32 -> COM-порт ПК -> DCT
```

```text
FPV-камера -> HDZeroVTX -> EventVRX -> карта/USB-захват -> DCT
```

Аппаратные компоненты:

- FPV-дрон исследуемого класса MADTrainer;
- EdgeTX/ELRS как протоколы работы приёмопередающего оборудования;
- ESP32 для парсинга данных с приёмника и передачи в ПК через COM-порт;
- HDZero EventVRX для сбора видеопотока с курсовой камеры;
- ПК/ноутбук для работы DCT.

## 8. Камерный модуль

- YOLO-модель обучалась самостоятельно в рамках работы.
- Обучение не было приоритетным направлением.
- Использовались настройки по умолчанию.
- Датасет малый: 100 вручную размеченных изображений из симулятора.
- Класс: `gate`.
- Разметка: 4 внутренних угла ворот как Skeleton.
- Реальный полёт проверял RC/PF-контур без YOLO/PnP.
- YOLO/PnP проверялся на записанных данных из симулятора.

## 9. Интеграция с "Небосвод"

Интеграция реализована через отдельное приложение **NebosvodConnect**:

- пользователь авторизуется в приложении;
- приложение принимает данные по MAVLink;
- пользователь выбирает свой БВС, предварительно заведённый в систему;
- пользователь выбирает поданный им план полёта;
- приложение передаёт данные в "Небосвод".

Текущее состояние MAVLink-интеграции:

- DCT отправляет `HEARTBEAT`;
- DCT отправляет `GLOBAL_POSITION_INT`;
- локальные координаты трассы переводятся в географические через три вручную
  заданные точки `origin`, `x`, `z`;
- пользователь самостоятельно вычисляет координаты точек привязки;
- скорость и курс пока не передаются и являются направлением дальнейшего
  развития;
- высота передаётся в упрощённом виде относительно выбранной геопривязки.

## 10. Архитектурная нотация C4

Диаграммы архитектуры ведутся в нотации **C4** (не произвольные блок-схемы).

- Исходник: `FinalQualifyingWork/figures/c4_dct_architecture.drawio`.
- Редактор: draw.io (diagrams.net) или VS Code + Draw.io Integration.
- Уровни: Context (гл. 1–2), **Container (п. 2.1)**, Component (гл. 3).
- Подробности: `figures/C4.md`.

В Word вставляется экспорт PNG/PDF из draw.io, не сам `.drawio`.

## 13. Мини-структура эксперимента (глава 3)

Каждый подраздел «Эксперимент N» (3.9.1–3.12.2) оформляется одинаково:

1. **Цель** — одно исследовательское утверждение.
2. **Описание** — постановка, данные, что именно сравнивалось.
3. **Условия и методика** — таблица факторов, параметров, объёма выборки.
4. **Результаты** — сводная таблица ключевых чисел (p90 и др.).
5. **Графики** — рисунки с подписями «Рисунок 3.x».
6. **Выводы** — интерпретация и решение для системы.

В `generate_vkr_docx.py` используется функция `experiment_block(...)`.
Нумерация в тексте: **Эксперимент 1–12** (не Exp 0–11).

## 14. Черновик v1.3 на основе v1.2

Скрипт `patch_draft_v13.py` копирует `БояриновИР_Дипломная v1.2.docx` в
`БояриновИР_ВКР_черновик.docx` и **встраивает** перекрёстные ссылки в текст
абзацев (не отдельными строками у подписей таблиц). Журнал правок —
`CHANGELOG_v13_черновик.md`.

Повторный запуск (после правок v1.2):

```bash
python FinalQualifyingWork/patch_draft_v13.py
```

Файл **v1.2 не изменяется**.

## 15. Правила обновления

- При добавлении новых численных результатов указывать источник: отчёт
  эксперимента, таблица, файл или скрипт.
- Пилотов в основном тексте обезличивать; реальные имена можно добавить позже в
  отдельном согласованном месте.
- Ограничения распределять по главам и кратко собирать в заключении.
- Не завышать результат по камере: реальный полёт был без YOLO/PnP; камерная
  часть проверялась на данных из симулятора.
- Раздел по NebosvodConnect оставить расширяемым до получения точного описания
  приложения.
