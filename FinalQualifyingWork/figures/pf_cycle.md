# Particle Filter — пояснение к блок-схеме `pf_cycle.drawio`

Документ идёт **в том же порядке**, что и блок-схема одного шага `ParticleFilter.update()` в DCT.  
Исходник кода: `dct/localization/online_localizer.py`, класс `ParticleFilter`.

---

## Идея в двух словах

Представьте **N гипотез** («частиц»): на каждой записано, где дрон на трассе (**s**, метры по дуге) и с какой скоростью он едет вдоль трассы (**v**, м/с). У каждой гипотезы есть **вес w** — насколько она правдоподобна.

На каждом шаге фильтр:

1. **раздувает** неопределённость (predict),
2. **сравнивает** гипотезы с реальными RC-стиками (weight update),
3. при необходимости **перерождает** частицы (resampling),
4. **усредняет** оставшиеся гипотезы с учётом круговой трассы (circular mean).

---

## Входные блоки (до основного цикла)

### Начало шага — `update(stick_norm, dt)`

**Что это:** один вызов фильтра, когда пришли новые данные с пульта.

| Величина | Смысл |
|----------|--------|
| `stick_norm` | Нормализованный вектор RC (обычно 4 канала: throttle, yaw, pitch, roll) в том же масштабе, что и референс |
| `dt` | Секунды с прошлого шага; на **первом** шаге часто `None` |

**Зачем `dt`:** без времени нельзя честно сдвинуть позицию по скорости: `s ← s + v·dt`.

---

### Вход: нормализованный вектор RC и `dt`

**Простыми словами:** «сейчас пилот держит стики вот так; прошло столько-то секунд».

Нормализация нужна, чтобы сравнивать текущие стики с **эталонной траекторией** (reference), где для каждой точки трассы тоже сохранён нормализованный вектор стиков.

---

## Условие 1: «Фильтр инициализирован?»

**В коде:** `if self._s is None: self.reset()`.

**Смысл ромба:** есть ли уже массивы частиц `_s`, `_v`, `_w`?

| Ответ | Что делаем |
|-------|------------|
| **Нет** | Вызов `reset()` |
| **Да** | Идём к проверке `dt` |

---

### Блок `reset()` (если не инициализирован)

**Зачем:** на старте полёта мы не знаем, на каком участке круга дрон — но знаем, что он где-то **около старта или около финиша** (круг замкнут).

**Математика простым языком:**

- Половина частиц: позиция около **0 м** (старт), с небольшим разбросом.
- Вторая половина: около **L м** (длина трассы / «финиш»), тоже с разбросом.
- Все позиции берутся по модулю: `s ← s mod L`, чтобы не выйти за длину круга.
- Скорости: случайные около `v_init` (например 10 м/с), но **обрезаны** в `[v_min, v_max]`.
- Веса: **все равны** `w_i = 1/N` — «пока ни одна гипотеза не лучше другой».

**Аналогия:** 1000 человек голосуют: «дрон либо в начале круга, либо в конце», с равной уверенностью.

## Условие 2: «dt задан и dt > 0?»

**В коде:** `if dt is not None and dt > 0:` — только тогда выполняется predict.

| Ответ | Что делаем |
|-------|------------|
| **Да** | Блок **1. Predict** |
| **Нет** | Сразу **2. Weight update** (типично первый кадр после reset) |

**Почему пропускают predict:** на первом измерении нет интервала времени — сдвигать `s` по `v·dt` нечем.

---

## 1. Predict (предсказание)

**Смысл:** «пока мы не увидели новые стики, каждая гипотеза немного **разъехалась** по трассе и по скорости».

Для **каждой** частицы (индекс `i` опущен для краткости):

### Шаг 1 — шум скорости

```
v ← v + случайное_число(центр=0, разброс=q_v·√dt)
v ← ограничить(v, v_min, v_max)
```

- `q_v` — параметр `process_noise_v`: насколько сильно «дрожит» скорость.
- Множитель `√dt`: чем дольше интервал, тем больше накопленная неопределённость.

**Простыми словами:** «скорость чуть изменилась случайно, но не стала абсурдной».

### Шаг 2 — сдвиг позиции

```
s ← s + v·dt + случайное_число(центр=0, разброс=q_s·√dt)
```

- `q_s` — `process_noise_s`: дополнительный шум позиции вдоль трассы.
- Слагаемое `v·dt` — обычная физика: «проехал столько-то метров за время dt».

### Шаг 3 — круговая трасса

```
s ← остаток_от_деления(s, L)
```

**Простыми словами:** трасса — **замкнутый круг** длиной **L** метров. Если гипотеза «уехала» за финиш, она снова у старта (как счётчик кругов).

**Аналогия:** часовая стрелка после 12 снова на 1 — так же `s` после L возвращается к началу.

---

## 2. Weight update (обновление весов)

**Смысл:** «какие гипотезы **лучше объясняют** текущие стики пилота?»

### Шаг A — найти эталон для каждой частицы

Для позиции `s` на референсе ищется ближайший узел (в коде `searchsorted` по массиву `ref.s`).  
Берётся вектор эталонных стиков `f_ref` в этой точке.

### Шаг B — невязка (насколько стики «не совпали»)

По каналам `k`:

```
diff_k = (f_ref,k − stick_k)²
```

Если заданы **веса каналов** `w_k` (`channel_weights`):

```
d² = сумма по k (diff_k · w_k)
```

иначе — просто сумма квадратов по всем каналам.

**Простыми словами:** `d²` — одно число «насколько плохо совпало». Чем **меньше** `d²`, тем гипотеза **лучше**.

Пример: можно обнулить вес throttle, чтобы сравнение не зависело от газа на другом дроне.

### Шаг C — новый вес (правдоподобие)

В коде считают в **логарифмах** (чтобы не было переполнения), смысл тот же:

```
w_new ∝ w_old · exp( −½ · d² / σ_obs² )
```

- `σ_obs²` — в коде `obs_sigma2_eff`: ширина «допуска» по стикам (связано с `obs_sigma` и числом каналов).
- Минус в экспоненте: **большая** невязка → **маленький** вес.

**Простыми словами:**  
«Если стики при текущей гипотезе почти как на эталоне — вес резко растёт. Если сильно отличаются — вес почти обнуляется».

После этого все веса **нормируют**, чтобы сумма была 1:

```
w_i ← w_i / (сумма всех w_j)
```

**Аналогия:** голосование: после нового измерения «плохие» гипотезы теряют голоса, «хорошие» получают почти все.

## Условие 3: «ESS < ess_thr · N?»

**ESS** (effective sample size) — «сколько частиц реально работают», а не одна доминирует.

```
ESS = 1 / (сумма по i: w_i²)
```

**Простыми словами:**

- Если веса **равные** (`1/N` каждому), то `ESS ≈ N` — все частицы «живые».
- Если **одна** частица весит почти 1, а остальные ~0, то `ESS ≈ 1` — фильтр **выродился** (все копии одной гипотезы).

**Порог:** `ess_threshold` (например 0.5) → ресемплинг, если `ESS < 0.5 · N`.

| Ответ | Действие |
|-------|----------|
| **Да** (мало эффективных частиц) | **3. Resampling** |
| **Нет** | Сразу **4. Circular mean** |

---

## 3. Resampling (ресемплинг)

**Смысл:** «убрать дубликаты супер-гипотез и **размазать** неопределённость снова».

### Систематический ресемплинг

По весам `w_i` случайно **выбирают N новых частиц** — чаще копируют те, у кого вес большой. В коде — систематическая схема (ровные шаги по накопленной сумме весов).

После копирования:

```
s ← s_копии + случайное_число(0, roughening_s)
s ← остаток_от_деления(s, L)
```

**roughening** — лёгкое «размазывание» позиций, чтобы частицы не стояли в одной точке.

Скорость копируется вместе с частицей: `v ← v_копии`.

### Random inject (только RC-шаг)

Доля `random_inject_frac` (например 2%) частиц **заново** кидается в случайное `s` по всей длине L:

```
s ← равномерно_от(0, L)
```

**Зачем:** если фильтр «залип» не там, есть шанс **восстановиться** на следующих измерениях.

После ресемплинга: **все веса снова** `w_i = 1/N`.

**Аналогия:** пересчитать голоса заново, но оставить 2% «диких карточек» с произвольной позицией на трассе.

> **Примечание:** при камерном апдейте (`inject_position_observation`) random inject **выключен** — см. § 3.5 ВКР.

## 4. Circular mean (оценка положения)

**Проблема:** обычное среднее `сумма(w_i·s_i) / сумма(w_i)` **ломается** на круге: точки у 0 м и у L м близки по смыслу, но далеки по числу.

**Решение:** перевести позицию в **угол** на окружности:

```
θ = 2π · s / L
```

Взвешенно посчитать «центр масс» на круге:

```
Cx = сумма(w_i · cos(θ_i))
Cy = сумма(w_i · sin(θ_i))
```

Угол результата:

```
θ̂ = atan2(Cy, Cx)
```

Обратно в метры:

```
s_est = θ̂ · L / (2π)
```

**Простыми словами:** как средний **азимут** на компасе — нельзя усреднять 359° и 1° как 180°, нужно через sin/cos.

### Неопределённость σ

```
R = √(Cx² + Cy²)
σ ≈ √(1 − R) · L / (2π)
```

- `R ≈ 1`: все гипотезы смотрят в одну сторону на круге → **уверенность высокая**, σ мала.
- `R ≈ 0`: гипотезы размазаны по всему кругу → **не уверены**, σ велика.

(В коде добавлен небольшой пол `max(1e-6, …)` для устойчивости.)

---

## Выход: `s_est`, σ

| Выход | Смысл |
|-------|--------|
| `s_est` | Оценка положения на дуге трассы, **метры** от условного старта |
| `σ` | Оценка разброса гипотез вдоль трассы, **метры** (индикатор неопределённости, не полноценный доверительный интервал) |

Дальше `OnlineLocalizer` переводит `s_est` в XYZ на трассе и отдаёт в KFLayer2 / GUI / MAVLink.

## Связь с таблицей параметров (§ 3.4)

| Параметр | Где на схеме | Роль в формулах |
|----------|----------------|-----------------|
| `n_particles` (N) | везде | число гипотез; входит в ESS-порог |
| `process_noise_v` (q_v) | Predict | шум скорости ∝ √dt |
| `process_noise_s` (q_s) | Predict | шум позиции ∝ √dt |
| `v_min`, `v_max` | Predict | ограничение скорости |
| `obs_sigma` | Weight update | ширина exp(−d²/(2σ²)) |
| `channel_weights` | Weight update | веса в сумме d² |
| `ess_threshold` | ромб ESS | ресемплинг если ESS < порог·N |
| `roughening_s` | Resampling | размазывание s после копирования |
| `random_inject_frac` | Resampling | доля «случайных» частиц на круге |

---

## Один шаг целиком (цепочка без индексов)

Упрощённо, на одном RC-шаге для каждой частицы:

1. `v ← clip(v + шум, v_min, v_max)`
2. `s ← (s + v·dt + шум) mod L`
3. `w ← w · exp(−d²/(2σ_obs²))`, нормировка
4. если ESS мал → ресемпл + roughening + (опционально) inject
5. `s_est`, σ` — circular mean по `{s, w}`
