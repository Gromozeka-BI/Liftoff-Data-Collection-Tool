# ТЗ на тестовые данные (локализация, Tracking-first, PnP)

Документ задаёт, **что нужно подготовить** для автоматических и ручных тестов конвейера «детекции ворот → присвоение `gate_id` → PnP». Полная покадровая разметка **целого круга не требуется**.

См. также общий план: [gate_id_localization.md](gate_id_localization.md).

## 1. Цели и виды тестов

| Цель | Нужны ли ваши кадры/разметка |
|------|------------------------------|
| **A. Юнит-тесты / синтетика** | Нет: данные генерируются в коде. |
| **B. Интеграция: карта + PnP + матчинг** | Да: кадры, углы ворот, `gate_id`, GT поза. |
| **C. Видео-трек: предсказание с предыдущего кадра** | Да + **последовательность** кадров с `frame_index` / именами. |

## 2. Минимальный обязательный набор

### 2.1. Кадры из одной сессии Liftoff

- **Разрешение:** как в датасете проекта (**1280×720**).
- **Формат:** PNG/JPG; имена файлов **уникальны** и стабильны (или содержат индекс кадра).
- **Объём:** не весь круг, а **три блока** по смыслу (достаточно десятков кадров на блок или меньше, если ограничено время):

| Блок | Описание | Зачем |
|------|----------|--------|
| **B1** | В кадре **ровно одна** хорошо видимая арка | Одна детекция, простой матчинг. |
| **B2** | **Две–три** арки одновременно | Совместное назначение ID и multi-gate PnP. |
| **B3** | «Сложный» случай (косой заход, дальняя дуга, сильный наклон, частичное перекрытие — по наличию) | Пороги отказа и регрессия. |

Непрерывный ролик всего заезда **не обязателен**.

### 2.2. Разметка на кадр (обязательные поля)

Для **каждого** кадра, включённого в тестовый набор:

| Поле | Требование |
|------|------------|
| `image_filename` | Точное имя файла изображения. |
| `frame_index` | Целое, порядок в записи (**рекомендуется** для сценария «предыдущий кадр → текущий»). |

Для **каждой видимой арки** в кадре (отдельная запись / объект в массиве `annotations`):

| Поле | Требование |
|------|------------|
| `gate_id` | Целое, из [`config/track.json`](../config/track.json). |
| Ключевые точки | Ровно **4** точки в пикселях, схема как в [`calibration/calibration_frames_card.json`](../calibration/calibration_frames_card.json): `inner_top_left`, `inner_top_right`, `inner_bottom_right`, `inner_bottom_left` — для каждой поля `x_px`, `y_px`. |

**Ground truth дрона на этот кадр** (как в существующей разметке):

- `position_world`: `x`, `y`, `z` (метры);
- `yaw_deg`;
- по возможности **`quaternion_world_body`** (если есть в телеметрии).

Ворота, которых **нет** в кадре, не размечаются.

### 2.3. Формат файла

**Предпочтительно:** один или несколько JSON в структуре, совместимой с [`calibration/calibration_frames_card.json`](../calibration/calibration_frames_card.json) (секции вроде `fov_frames` / `multi_frames` или отдельный массив кадров — главное, чтобы парсер тестов мог однозначно прочитать список кадров, аннотации и `ground_truth`).

**Допускается:** CSV/Excel с колонками:

`filename`, `frame_index`, `gate_id`, `tl_x, tl_y, tr_x, tr_y, br_x, br_y, bl_x, bl_y`, `gt_x, gt_y, gt_z`, `gt_yaw_deg`  
(при нескольких арках на кадр — **несколько строк** с тем же `filename`).

## 3. Рекомендуемые дополнения (не блокируют старт)

| Данные | Зачем |
|--------|--------|
| **10–30 подряд идущих кадров** в одном из блоков | Тест Tracking-first: предсказание = оценка/GT **предыдущего** кадра. |
| `frame_telemetry.json` или аналог для той же сессии | Привязка времени и кадров без ручного поиска. |
| Пометка кадров с **подозрением на лаг телеметрии** | Отдельные мягкие пороги или исключение из строгих метрик. |

## 4. Что не требуется

- Покадровая разметка **всего** круга.
- Разметка классов для обучения детектора «с нуля» — для тестов матчинга и PnP достаточно **ручных углов + `gate_id`**; детектор в тестах можно **заменить** этими точками.
- Отдельный файл, если все поля уже есть в расширенном `calibration_frames_card.json`.

## 5. Критерии приёмки набора

- Файл изображения существует для каждой записи в разметке.
- У каждой аннотации: валидный `gate_id` из карты трассы; четыре угла **внутри** изображения (или явно помеченные исключения для частичной видимости).
- Для тестов, которые сравнивают ошибку позы с GT: у каждого такого кадра заполнены **позиция** и **yaw** (и кватернион — если тесты его используют).

## 6. Связь с кодом

- Карта ворот: [`src/gate_model/gate_model.py`](../src/gate_model/gate_model.py), вход [`config/track.json`](../config/track.json).
- Камера: [`config/camera_calibration.json`](../config/camera_calibration.json).
- PnP: [`src/pnp_solver/pnp_solver.py`](../src/pnp_solver/pnp_solver.py).

## 7. Краткий чеклист для поставщика данных

1. Три блока кадров: **B1** (1 арка), **B2** (2–3 арки), **B3** (сложный случай).
2. На каждый кадр: `image_filename`, желательно `frame_index`.
3. На каждую видимую арку: `gate_id` + 4 ключевые точки (`x_px`, `y_px`).
4. На каждый кадр: GT `position_world`, `yaw_deg` (+ кватернион по возможности).
5. Опционально: непрерывный фрагмент 10–30 кадров и телеметрия сессии.
