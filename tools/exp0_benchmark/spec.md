## 1. Исследовательский вопрос

> Какой из рассматриваемых методов локализации по стикам RC обеспечивает
> наилучшую точность на track-002, и почему был выбран именно фильтр частиц?

---

## 2. Предшествующие знания

Ранее бенчмарк проводился на другом треке. Текущий эксперимент — повтор
на track-002 с теми же данными, что используются в Exp 1–4. Это обеспечивает
прямую сравнимость результатов бенчмарка и последующих экспериментов.

---

## 3. Сравниваемые методы

| Метод | Описание |
|---|---|
| **Particle Filter** (выбранный) | Байесовский фильтр частиц — текущая реализация DCT |
| **DTW** | Dynamic Time Warping — сопоставление временных рядов |
| **DTW + скользящее окно** | DTW с ограниченным окном поиска |
| **Nearest Neighbour** | Простейший k-NN по вектору стиков |
| *(другие из bench)* | По составу репозитория `stick_localizer_bench` |

---

## 4. Гипотезы

| # | Гипотеза | Ожидаемый результат |
|---|---|---|
| H1 | Particle Filter превосходит DTW по p90 в кросс-дроновом сценарии | p90(PF) < p90(DTW) |
| H2 | PF превосходит NN по скорости восстановления после ошибок | jump_rate(PF) < jump_rate(NN) |
| H3 | Все методы улучшаются при RC+Rate режиме vs RC | Монотонный рост при нормализации |

## 5. Дизайн

**Данные**: track-002, те же 4 сессии что в Exp 1–4.  
**Референс**: GromFF_1.npz (как в Exp 1–4).  
**Режимы**: RC+Rate (основной), RC-only (для сравнения).  
**Гиперпараметры**: для каждого метода — дефолтные из bench (не оптимизировать).

**Фиксировано**: N_LAST_LAPS=3, JUMP_THRESHOLD=15 м.

- Вторичные: `median_err_m`, `jump_rate`, время выполнения (мс/кадр)
