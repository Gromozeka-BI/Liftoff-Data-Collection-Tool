## 1. Исследовательский вопрос

> Какой из рассматриваемых методов локализации по стикам RC обеспечивает
> наилучшую точность, и почему был выбран именно фильтр частиц?

Сравнение проводится на **двух трассах разной сложности**:
- **track-001** (Первая трасса) — простая трасса, *single-drone* сценарий (один дрон, сессия из 20 кругов).
- **track-002** — более сложная трасса, **cross-drone** сценарий (4 сессии, 2 разных дрона: MadTrainer и LiftOff_200).

Двойной анализ позволяет:
1. Проверить устойчивость ранжирования методов в зависимости от трассы и сценария;
2. Воспроизвести предыдущий бенчмарк (track-001) с теми же реализациями методов, что используются в Exp 1–4 (track-002).

## 2. Предшествующие знания

Ранее бенчмарк выполнялся «по умолчанию» на одиночной сессии track-001.
Текущий эксперимент:
- **повторяет** этот бенчмарк на track-001 — для полной сопоставимости с архивными результатами;
- **расширяет** его на track-002 с теми же данными, что используются в Exp 1–4 — для прямой сравнимости с последующими экспериментами.

## 4. Гипотезы

| # | Гипотеза | Ожидаемый результат |
|---|---|---|
| H1 | Particle Filter превосходит DTW и NN по медианной ошибке | median(PF) ≤ median(DTW), median(PF) ≤ median(NN_window) |

## 5. Дизайн

**Режим оценки**: leave-one-out (LOO) — каждый круг по очереди берётся как эталон,
оставшиеся круги используются как тестовые. Это даёт `n × (n-1)` независимых оценок
на трассу для каждого метода.

**track-001**:
- Источник: `D:\DroneTrackerDB\Liftoff\Part_1\2026-05-05_pilot-Gromozeka_drone-MadTrainer_track-Первая трасса_session-009`
- Дрон: MadTrainer (single-drone сценарий)
- Круги: **только из этой сессии** (20 кругов)
- LOO-прогонов: 20 × 19 = 380 на метод

**track-002**:
- Источник: `D:\DroneTrackerDB\Liftoff\Part_5_Эксперементальный` (4 сессии)
- Дроны: MadTrainer + LiftOff_200 (cross-drone сценарий, как в Exp 1–4)
- Круги: ~20 (после фильтрации аномальных)
- LOO-прогонов: ~20 × 19 = ~380 на метод

**Гиперпараметры методов**: дефолтные из репозитория `stick_localizer_bench`
(не оптимизируются, чтобы сравнение было «честным» — каждый метод в своих
рекомендованных настройках).

**Возмущение стиков (`--deltas`)**: 0 (без искусственного шума).

## 6. Метрики

Для каждой пары (ref_lap, test_lap) вычисляются (см. `metrics.py`):

| Метрика | Описание | Приоритет |
|---|---|---|
| `median` | Медианная ошибка позиции (м) на круге | **Первичная** |
| `p95` | 95-й перцентиль ошибки (м) на круге | Вторичная |
| `pct_under_2m`, `pct_under_5m` | Доля кадров с ошибкой < 2 м / < 5 м | Вторичная |
| `tracking_pct` | 100 − (% «откатов» назад по s) | Вторичная |
| `latency_p95_ms` | 95-й перцентиль времени `update()` (мс) | Real-time |

Агрегация: среднее по всем LOO-парам (ref, test) для каждого метода → таблица в `summary.csv`.

## 7. Как запустить

Из корня репозитория DCT:

```powershell
python tools\exp0_benchmark\run_bench.py
```

Скрипт последовательно запускает `benchmark_v2.py --mode loo` для обоих треков,
складывает результаты в `tools/exp0_benchmark/track001/` и `tools/exp0_benchmark/track002/`.

После завершения — агрегация и построение отчёта:

```powershell
python tools\exp0_benchmark\aggregate.py
```
