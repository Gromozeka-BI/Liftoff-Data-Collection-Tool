## 5. Выводы

### 5.1. Главное открытие: усреднение по N лапам — асимметричный эффект

Самый сильный сигнал в эксперименте — **рост `n_laps` помогает только в cross-drone сценарии**:

| n_laps | same_drone p90 | cross_drone p90 | разница cross |
|---|---|---|---|
| 1 | 11.92 м | 15.33 м | базовая |
| 3 | 12.27 м | 10.98 м | **−28%** |
| 5 | 13.24 м | **8.51 м** | **−45%** |

**Почему это происходит.** Каждый отдельный круг содержит две компоненты сигнала:
1. **Систематическая** — реальный отклик дрона на стики в каждой точке трассы.
2. **Стохастическая** — высокочастотные особенности конкретного полёта (микро-коррекции, шум стиков, индивидуальные привычки).

При усреднении по N лапам стохастика подавляется как `1/√N`, а систематическая часть остаётся.

- В **same-drone** сценарии тестовый дрон сам генерирует ту же стохастику, что в референсе → она работает как «дополнительный отпечаток» и помогает локализации. Усреднение её разрушает → качество немного падает.
- В **cross-drone** сценарии тестовый дрон генерирует ДРУГУЮ стохастику → совпадение случайно. Усреднение референса убирает помеху, оставляя только обобщаемую часть отклика → качество резко растёт.

**Практический вывод:** для системы, рассчитанной на обобщение между дронами/пилотами, усреднение по 5 лапам — обязательный приём. Для сценария «один пилот, один дрон» можно использовать одиночный круг без потери качества.

### 5.2. Лучшая конфигурация cross-drone: median_time + n=5 + sw=5 → p90 7.25 м

Это **на 25% лучше**, чем GromFF_1 (Exp 4 cross-drone p90 = 9.7 м), при том что Exp 4 уже считался отличным результатом. Это означает: **Exp 4 недооценил потенциал референса** — он использовал один лап, и оптимизация шла только по гиперпараметрам PF.

### 5.3. Стратегия выбора лапа — три неожиданности

| lap_selection | same_drone p90 | cross_drone p90 |
|---|---|---|
| `fastest` | **8.63** | 12.41 |
| `median_time` | 10.83 | **8.93** |
| `manual_best` | 17.97 | 13.48 |

#### Сюрприз №1: `manual_best` — худшая стратегия (хотя должна быть лучшей)

`manual_best` ранжирует лапы по среднему NN-greedy расстоянию (LOO-схема): чем меньше — тем «качественнее» лап. Эта эвристика заложена в `dct/localization/reference_select.py` и используется GUI-кнопкой «Auto-pick». Но она оптимизирует **другую** функцию потерь:

- **NN-greedy** награждает лапы, которые при z-score normalization ближе к остальным лапам в пространстве стиков.
- На практике это означает **низковариативные лапы** — спокойные, без резких манёвров.
- Но низкая вариативность референса = слабые **distinctive features** на каждом сегменте трассы → PF путает похожие отрезки.

**Это методологический вывод:** метрика качества референса должна совпадать с тестовым алгоритмом. NN-greedy ранжирование — артефакт раннего этапа разработки, его нужно **заменить на PF-based ranking** в GUI (или хотя бы добавить альтернативу).

#### Сюрприз №2: `fastest` лучше для same-drone, хуже для cross-drone

«Самый быстрый круг» — это лап с самыми агрессивными манёврами (полный газ, резкие повороты, агрессивный roll). Дрон достигает их, выжимая максимум из своих rate-настроек.

- В same-drone: тестовый дрон точно так же выжимается на тех же сегментах → стик-паттерны совпадают идеально → отличный матчинг.
- В cross-drone: «выжатые» состояния обоих дронов **отличаются больше всего** (разный max yaw rate, разный отклик на пиковые стики). Ошибка концентрируется именно на агрессивных участках → cross-drone с `fastest` хуже.

#### Сюрприз №3: `median_time` — самая универсальная стратегия

«Типичный по времени» лап — самый репрезентативный, без экстремумов. Он:
- проигрывает `fastest` на same-drone всего на 2.2 м (10.83 vs 8.63);
- выигрывает у всех на cross-drone (8.93 м);
- не проваливается ни в одном сценарии.

**Рекомендация для GUI:** дефолтную стратегию `select_best_reference` заменить на `median_time` (или сделать её комбинацией: `median_time` + усреднение по 3–5 ближайших к медиане лапов).

### 5.4. Сглаживание (`smooth_w`) — слабый фактор

Все значения в диапазоне `smooth_w ∈ [1..15]` дают p90 в коридоре 10.55–14.58 м (same) и 11.20–12.24 м (cross). Эффект меньше, чем разница между двумя соседними `lap_selection` на 4–6 м.

**Почему?** PF уже выполняет двойное сглаживание самостоятельно:
1. **Внешнее**: буфер последних `smooth_w` входящих стиков → moving average перед нормализацией.
2. **Внутреннее**: распределение частиц по `s` шириной ≈ `obs_sigma=2 м` эффективно усредняет наблюдения по сегменту трассы.

Дополнительное сглаживание на этапе сборки референса работает «по верх» уже сглаженного PF-конвейера → marginal эффект. Гипотеза H1 (`smooth_w↑ → p90↓`) **отклонена** как раз потому, что главный канал сглаживания не в референсе, а в самом фильтре.

### 5.5. Согласованность гиперпараметров (H4): smooth_w=3 для всех

Оптимум `smooth_w=3` совпадает для same- и cross-drone. Это означает, что **оптимальная сборка референса не зависит от целевого сценария тестирования** — можно собрать ОДИН референс и использовать его и для same-, и для cross-drone задач без потери оптимальности. Полезное упрощение для пользователя GUI.

### 5.6. Что делать с этими результатами в продакшен-DCT

| Изменение | Где | Ожидаемый эффект |

### 5.7. Связь с другими экспериментами

- **Exp 0**: показал, что PF — оптимальный алгоритм; здесь подтверждено, что и **построение референса** для PF имеет свою специфику, не наследуемую от NN-greedy.
- **Exp 3**: оптимизировал `obs_sigma=2.0`, `pnv=8.0`. Эти параметры использованы фиксированными — значит выигрыш в 7.25 м чистый эффект стратегии референса.
- **Exp 4**: показал «качество референса важнее типа дрона». Этот эксперимент **раскрывает, что именно делает референс качественным**: усреднение и разумный выбор лапа, а не «лучший по эвристике».
