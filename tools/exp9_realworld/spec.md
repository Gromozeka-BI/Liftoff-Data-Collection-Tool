# Эксперимент 9: Реальный трек — точность в контрольных точках

## Статус: ДАННЫЕ ГОТОВЫ → ЗАПУСКАТЬ

---

## 1. Исследовательский вопрос

> Сохраняется ли точность системы (p90 < 15 м) при переходе от симулятора
> к реальному полёту на физической трассе?

Это **валидационный эксперимент**: все предыдущие эксперименты (Exp 0–8)
проводились в симуляторе Liftoff. Здесь проверяем, работает ли система
в реальных условиях (шум сенсоров, вибрации рамы, реальная физика).

---

## 2. Предшествующие знания

- Exp 0–8: система достигает p90 = 5.8–9.7 м в симуляторе.
- Реальный полёт отличается: шум гироскопа выше, нет идеальной RC-телеметрии.
- Exp 5: cross-pilot ошибка ~66 м (baseline) → ~17 м (angular_scaled). Пилотский
  стиль — доминирующий фактор.
- Exp 8: новые трассы требуют sigma=4.0 вместо 2.0.
- В реальном полёте нет непрерывного ground truth → используем дискретные
  контрольные точки (ворота трассы, аннотированные из FPV-видео).

## 4. Дизайн эксперимента

### Матрица условий

```
5 референсов × 2 полётные сессии × 3 пресета весов
```

**Варианты:**
- **Variant B (real→real):** RedRC_2, RedRC_3 — потолок точности на реальных данных
- **Variant A (sim→real):** Grom_4, Grom_5, PlatOnAir_T1 — переход симулятор→реальность

**Пресеты весов:**
- `baseline [1, 1, 1, 1]`
- `no_thr [0, 1, 1, 1]` (лучший в Exp 3)
- `angular_scaled [0, 0.7, 0.5, 1]` (лучший в Exp 5 для cross-pilot)

**Фиксированные гиперпараметры (Exp 3):**
- obs_sigma = 2.0 (дополнительно тестируем 4.0 — лучший для новых трасс, Exp 8)
- process_noise_v = 8.0
- v_init: вычисляется из L и длины референса

### Механизм ground truth

1. `button_gate(gate_id)` event → timestamp `t_gate`
2. Ближайший RC-кадр к `t_gate` → запись `s_est(t_gate)` из локализатора
3. Позиция ворот из `track.json` → проекция на `ref.pos` → `s_gate[gate_id]`
4. `gate_error = |s_est - s_gate|` (с wrap по L/2)
