# Эксперимент 9: Реальный трек — точность в контрольных точках

## Статус: ОЖИДАЕТ ПОДГОТОВКИ ТРАССЫ

Вариант проведения: **A (минимальный)** — аннотация по FPV-видео.

---

## 1. Исследовательский вопрос

> Сохраняется ли точность системы (p90 < 15 м) при переходе от симулятора
> к реальному полёту на физической трассе?

Это **валидационный эксперимент**: все предыдущие эксперименты проводились
в симуляторе Liftoff. Данный эксперимент проверяет, работает ли система
в реальных условиях (шум сенсоров, ветер, вибрации рамы).

---

## 2. Предшествующие знания

- Exp 1–4: система достигает p90=5.8–9.7 м в симуляторе.
- Реальный полёт отличается: шум гироскопа выше, задержки управления, влияние ветра.
- В реальном полёте нет непрерывной телеметрии → используем дискретные контрольные точки.

---

## 3. Подготовка трассы (что нужно сделать)

### 3.1 Физическая трасса

- Построить трассу, аналогичную track-002 из симулятора
- Рекомендуемое количество ворот/элементов: **6–8**
- Трасса должна образовывать замкнутый круг (как в симуляторе)

### 3.2 Разметка контрольных точек

Выбрать **4–5 маркеров** с чёткими визуальными ориентирами:

| Маркер | Рекомендация |
|---|---|
| M1 | Стартовая линия (обязательно) |
| M2 | После первого поворота |
| M3 | Середина трассы |
| M4 | Перед последними воротами |
| M5 | *(опционально)* 3/4 круга |

**Для каждого маркера измерить arc-длину `s_gate` (м)** — расстояние вдоль
трассы от старта до маркера (рулеткой по линии полёта).

### 3.3 Построить референс

Записать несколько тренировочных лапов в **RC-only режиме** (без симулятора),
построить референс через DCT GUI.

*Примечание: поскольку трасса реальная, для построения референса потребуется
режим ручной разметки позиций (arc-parameter fitting) — уточнить в GUI DCT.*

---

## 4. Процедура полёта

1. Установить камеру на запись FPV-видео (OSD с таймером если возможно)
2. DCT запущен, режим **RC-only**
3. Лететь **5–8 лапов** последовательно без остановки
4. После полёта — аннотировать видео

---

## 5. Аннотация по видео

Для каждого лапа, для каждого маркера:
1. Найти кадр, где маркер появляется в **центре** FPV-изображения
2. Записать **timestamp** кадра (или номер кадра × frame_rate)
3. Заполнить таблицу: `lap_id, marker_id, s_gate, t_crossing`

Шаблон файла аннотации: `annotations.csv`
```
lap_id, marker_id, s_gate_m, timestamp_s
1, M1, 0.0, 3.45
1, M2, 18.3, 6.12
...
```

---

## 6. Метрики

В реальном эксперименте нет непрерывного `s_real`, поэтому метрика другая:

| Метрика | Формула | Смысл |
|---|---|---|
| `gate_error_m` | `|s_est(t_gate) - s_gate|` | Ошибка в контрольной точке |
| `mean_gate_error` | Среднее по всем воротам и лапам | Аналог median_err_m |
| `p90_gate_error` | 90-й перцентиль gate_error | Аналог p90_err_m |

---

## 7. Дизайн

**Конфигурация локализатора**: оптимальная из Exp 3 (`sigma=2.0, pnv=8.0, no_thr`).  
**Режим**: RC-only (реальный полёт не имеет rate-калиброванных данных из симулятора —
нужно проверить, можно ли использовать RC+Rate с реальным rate_profile).

---

## 8. Гипотезы

| # | Гипотеза | Ожидаемый результат |
|---|---|---|
| H1 | p90_gate_error < 15 м на реальной трассе | Подтверждено или нет |
| H2 | p90_gate реального полёта выше симулятора, но < 2× | p90_real < 2 × p90_sim |
| H3 | Ошибка не накапливается от ворот к воротам (нет drift) | gate_error не растёт с номером ворот |
