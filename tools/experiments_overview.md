## Ключевые результаты завершённых экспериментов

| Эксперимент | Главный вывод |
|---|---|
| Exp 0 | Particle Filter — лидер на обеих трассах: median 1.60 м (track-001) / 3.60 м (track-002, cross-drone), latency p95 < 0.5 мс. Все 4 гипотезы подтверждены. |
| Exp 1 | RC+Rate — оптимальный режим. Тип дрона — доминирующий фактор (eta²=0.41). |
| Exp 2 | `angular_scaled [0,0.7,0.5,1]` и `no_thr [0,1,1,1]` снижают cross-drone p90 до ~21 м. |
| Exp 3 | sigma=2.0, pnv=8.0 достигают cross-drone p90=**7.8 м** (цель < 15 м **достигнута**). |
| Exp 4 | Качество референса важнее типа дрона. GromFF_1 cross-drone p90=9.7 м (лучше same-drone LO200). |
| Exp 6 | Усреднение по 5 лапам почти вдвое снижает cross-drone p90 (15.3→8.5 м). Лучшая конфигурация: median_time + n=5 + sw=5 → cross-drone p90=**7.25 м**. `manual_best` (NN-greedy ранжирование) хуже всех — не переносится на PF. |
| Exp 7 | На горизонте 14-15 лапов (~6 мин полёта) **временной деградации нет**. Continuous ≈ reset (ΔP90=−0.02 м) → сбрасывать фильтр между лапами не нужно. Cold-start сходится <1 лапа (H3 ✗). Cross-drone оказался стабильнее same-drone (H2 ✗): LO_s001 mean p90=**6.49 м**, рекорд для трассы. Главный источник ошибок — **выбросы на конкретных лапах** (пилот-зависимый шум), не время. Реф следует строить из сессий той же серии полётов. |
| Exp 8 | Дефолтные параметры Exp 3 (σ=2.0) **не переносятся** на новые трассы: на track-003 default σ=2.0 даёт mean p90=**67.5 м** (катастрофа), на track-004 — 11.2 м (граница). H1, H2, H3 ОПРОВЕРГНУТЫ. **Mini-sweep нашёл оптимум σ=4.0 на обеих новых трассах** — даёт mean p90 **6.7 м** (track-003) и **6.4 м** (track-004), что лучше track-002 cross-drone (7.1 м). Причина — не геометрия, а **зрелость данных**: новые трассы записаны за один день, пилот менее консистентен → нужен больший σ. PNV одинаков на всех трассах (8.0). Для DCT: сделать σ адаптивным или per-track; дефолт для свежих трасс σ=4.0. |
| Exp 10 | Камерная фьюжн (3D Bayes-update в `inject_position_observation`) **резко улучшает** локализацию: same-drone p90 12.4→2.5 м (−80%), cross-drone 6.5→1.9 м (−70%) при σ_cam=1м, T=0.2с. Насыщения по частоте нет (H2 ✗), cross-drone выигрывает в % меньше из-за лучшей базы (H3 ✗). **Шумная камера (σ≥10м, T≥1с) активно вредит** cross-drone (10.1м vs 6.5м baseline) — лучше отключать (H4 ✗). Целевые требования к камере: **σ_cam ≤ 3м @ ≥ 2 Гц** → ожидаемый p90 ≤ 4 м. Полное ТЗ — в `camera_requirements.md`. **HP-frontier (σ_cam ≤ 1м, частоты до 100 Гц)**: max потолок **p90=0.51м (cross) / 1.18м (same)** при σ_cam=0.1м @ 5–10 Гц — на порядок лучше baseline, на уровне размера дрона. Дальше частоту/точность поднимать бесполезно: PF теряет устойчивость (бимодальность), нижняя граница ошибки определяется не камерой, а шагом референса (~0.3м/узел). |

## Формальные правила построения экспериментов

### 1. Структура эксперимента

Каждый эксперимент **обязан содержать**:

```
1. Исследовательский вопрос      — одно предложение
2. Предшествующие знания          — что уже известно из предыдущих Exp
3. Гипотезы H1..Hn               — конкретные, проверяемые, с ожидаемым результатом
4. Дизайн                         — матрица факторов × уровней + фиксированные параметры
5. Метрики                        — первичная и вторичные
6. Результаты                     — таблицы, числа, подтверждение/опровержение гипотез
7. Выводы и рекомендации          — для системы и для диплома
8. Файлы                          — список всех выходных файлов
```

### 2. Правила именования

- Папка: `tools/expN_shortname/` (например, `exp3_hyperparam/`)
- Скрипт: `tools/experiment_shortname.py`
- Короткое имя: 1–2 слова, латиница, подчёркивание

### 3. Стандартная структура выходной папки

```
expN_shortname/
├── spec.md              ← описание эксперимента (до запуска)
├── results.csv          ← per-observation данные
├── summary.csv          ← агрегированные по (условие, пресет, ...)
├── report.md            ← финальный отчёт (после запуска)
├── anova.txt            ← статистика (если ≥2 факторов)
└── plots/
    └── *.png
```

### 4. Метрики (обязательны для всех)

| Метрика | Описание | Приоритет |
|---|---|---|
| `p90_err_m` | 90-й перцентиль ошибки (м) | **Первичная** |
| `median_err_m` | Медианная ошибка (м) | Вторичная |
| `jump_rate` | Доля кадров с ошибкой > 15 м | Вторичная |

### 5. Статистика

- При ≥2 факторах — двухфакторный ANOVA, эффект-размер eta²
- Уровни значимости: `*` p<0.05, `**` p<0.01, `***` p<0.001, `n.s.` — незначимо

### 6. Правило фиксации параметров

> Если параметр не является фактором данного эксперимента — используй значение
> из таблицы «Фиксированные параметры по умолчанию» выше. Фиксацию обосновывай
> явно в разделе «Дизайн» отчёта.

### 7. Формат гипотез

```
H1: [Утверждение]. Ожидаемый результат: [конкретное числовое или направленное предсказание].
```

### 8. Правило базовой линии

Каждый эксперимент должен включать хотя бы одно условие, воспроизводящее
результат предыдущего эксперимента (для проверки согласованности данных).
