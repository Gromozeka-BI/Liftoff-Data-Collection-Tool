## Общие выводы по всей серии экспериментов

### Система

Разработанная система локализации дрона на основе **фильтра частиц (Particle Filter)**
и RC-стиков с пересчётом в угловые скорости через профиль рейтов (режим RC+Rate)
**доказала свою работоспособность** — от симулятора до реального полигона.

**Итоговые характеристики системы (best configuration):**

| Условие | p90 (м) | Конфигурация | Эксперимент |
|---------|---------|-------------|------------|
| Same-drone, same-pilot (потолок) | **6.5 м** | RC+Rate, σ=2.0, no_thr | Exp 7 |
| Cross-drone, same-pilot | **7.25 м** | RC+Rate, σ=2.0, avg 5 laps | Exp 6 |
| Cross-drone, cross-pilot | **17.7 м** | RC+Rate, σ=2.0, angular_scaled | Exp 5 |
| Новая трасса (симулятор) | **6.4 м** | RC+Rate, σ=4.0, no_thr | Exp 8 |
| Реальный полигон (реальный реф) | **10.9 м** | RC+Rate, σ=2.0, no_thr | Exp 9 |
| Реальный полигон (sim-реф) | **9.4 м** | RC+Rate, σ=4.0, angular_scaled | Exp 9 |
| С камерной фьюжн (σ_cam=1м, 5Гц) | **1.9 м** | RC+Rate + camera | Exp 10 |

**Целевой порог p90 < 15 м выполнен** во всех сценариях кроме cross-pilot
с неоптимальным пресетом.

### Выводы по факторам влияния

**1. Метод локализации (Exp 0)**
Particle Filter превосходит все альтернативы (KF, HMM, DTW) на обеих трассах.
Выбор PF обоснован количественно: median 1.60 м на track-001, latency < 0.5 мс.

**2. Режим наблюдения: RC+Rate — обязателен (Exp 1)**
Простые RC-стики не работают для cross-drone (ошибка растёт в разы). Пересчёт в
угловые скорости через индивидуальный профиль рейтов нейтрализует разницу железа.
Тип дрона — самый сильный источник вариации (eta²=0.41), сильнее пилота и трассы.

**3. Веса каналов (Exp 2–3)**
Газ (throttle) — бесполезный или вредный канал в cross-drone/cross-pilot сценариях:
его обнуление (`no_thr`, `angular_scaled`) стабильно улучшает обобщаемость.
`angular_scaled [0, 0.7, 0.5, 1]` — лучший выбор для межпилотной и межреальной
обобщаемости; `no_thr [0, 1, 1, 1]` — для однопилотных сценариев.

**4. Гиперпараметры (Exp 3)**
Оптимум σ=2.0, pnv=8.0 устойчив для хорошо знакомых трасс и пилотов.
Для новых трасс и реальных данных — σ=4.0 (больший радиус захвата). σ не зависит
от геометрии трассы, а от зрелости данных (число сессий, консистентность пилота).

**5. Качество референса (Exp 4, 6)**
Хороший референс важнее совпадения дрона. Референс, построенный из нескольких
усреднённых лапов (n=5), даёт p90=7.25 м — лучший результат без камеры.
Строить референс нужно из сессий той же серии полётов, что и тест.

**6. Пилот — доминирующий источник неопределённости (Exp 5)**
Стиль пилотирования влияет сильнее, чем тип дрона (~2× хуже при cross-pilot).
Рекомендация: строить собственный референс для каждого пилота. Если невозможно —
использовать `angular_scaled` + ближайший по скорости пилот.

**7. Временна́я стабильность (Exp 7)**
Фильтр не деградирует со временем — сбрасывать его между кругами не нужно.
Главный источник ошибок — выбросы на отдельных кругах, а не накопленный дрейф.

**8. Обобщаемость на новые трассы (Exp 8)**
Оптимальные параметры с одной трассы не переносятся без настройки. Достаточно
mini-sweep по σ (3–5 значений): оптимум находится быстро и даёт p90 < 7 м.

**9. Реальный мир (Exp 9)**
Барьер симулятор→реальность преодолён при правильном выборе пилота-донора референса.
Ключевое условие: скорость пилота референса и тест-пилота должны совпадать (±20%).

**10. Камерная фьюжн — следующий шаг (Exp 10)**
Даже редкие абсолютные обновления позиции (σ_cam=1м, 5 Гц) снижают p90 в 3–5 раз.
Это определяет приоритет следующего этапа работы: построение системы определения
позиции по курсовой камере.

```

  obs_sigma = 4.0,  pnv = 8.0,  weights = angular_scaled, ref = 1 lap
```

## Формальные правила построения экспериментов

### 1. Структура эксперимента

Каждый эксперимент **обязан содержать**:

```
1. Исследовательский вопрос      — одно предложение
2. Предшествующие знания          — что уже известно из предыдущих Exp
3. Гипотезы H1..Hn               — конкретные, проверяемые, с ожидаемым результатом
4. Дизайн                         — матрица факторов × уровней + фиксированные параметры
5. Метрики                        — первичная и вторичные
6. Результаты                     — таблицы, числа, подтверждение/опровержение гипотез
7. Выводы и рекомендации          — для системы и для диплома
8. Файлы                          — список всех выходных файлов
```

### 2. Правила именования

- Папка: `tools/expN_shortname/` (например, `exp3_hyperparam/`)
- Скрипт: `tools/experiment_shortname.py`
- Короткое имя: 1–2 слова, латиница, подчёркивание

### 3. Стандартная структура выходной папки

```
expN_shortname/
├── spec.md              ← описание эксперимента (до запуска)
├── results.csv          ← per-observation данные
├── summary.csv          ← агрегированные по (условие, пресет, ...)
├── report.md            ← финальный отчёт (после запуска)
├── anova.txt            ← статистика (если ≥2 факторов)
└── plots/
    └── *.png
```

### 4. Метрики (обязательны для всех)

| Метрика | Описание | Приоритет |
|---|---|---|
| `p90_err_m` | 90-й перцентиль ошибки (м) | **Первичная** |
| `median_err_m` | Медианная ошибка (м) | Вторичная |
| `jump_rate` | Доля кадров с ошибкой > 15 м | Вторичная |

### 5. Статистика

- При ≥2 факторах — двухфакторный ANOVA, эффект-размер eta²
- Уровни значимости: `*` p<0.05, `**` p<0.01, `***` p<0.001, `n.s.` — незначимо

### 6. Правило фиксации параметров

> Если параметр не является фактором данного эксперимента — используй значение
> из таблицы «Фиксированные параметры по умолчанию» выше. Фиксацию обосновывай
> явно в разделе «Дизайн» отчёта.

### 7. Формат гипотез

```
H1: [Утверждение]. Ожидаемый результат: [конкретное числовое или направленное предсказание].
```

### 8. Правило базовой линии

Каждый эксперимент должен включать хотя бы одно условие, воспроизводящее
результат предыдущего эксперимента (для проверки согласованности данных).
